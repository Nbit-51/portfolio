01 / Who I Am

I build things, then study why they work.

Obsessed with how models actually run — not just what they predict.

WHAT I'M WORKING ON

My focus right now is inference-time efficiency — how attention mechanisms, memory bandwidth, and kernel fusion interact to bottleneck model serving, on any hardware. I test this empirically on both ends of the spectrum: fused Triton/CUDA kernels (Hydra Engine) when a GPU is available, a from-scratch AVX2 CPU runtime (Leaf) when it isn't, and KV cache eviction strategies under RoPE-based architectures on the research side. The projects are how I validate the theory, not the point in themselves.

CURRENT RESEARCH STATUS

KV cache compression methodology — comparing budget truncation, H2O eviction, and sliding window attention — has been validated on smaller-parameter variants across OPT, IBM Granite, and Qwen2.5 architectures. I'm now scaling evaluation to larger-parameter models to confirm the trend holds before TMLR submission.

WHERE THIS IS GOING

I want to build inference-layer software that makes deep learning models faster, leaner, and hardware-efficient at scale — working at the intersection of AI compilers, GPU programming, and low-overhead model deployment systems.

Technical Thesis
Most inference slowdowns aren't algorithmic — they're memory-bound. Every project here is an attempt to close the gap between what a model could do on a given piece of silicon and what it actually does, one fused kernel or cache eviction policy at a time.

02 ACTIVE DEVELOPMENT
CPU INFERENCE Leaf

A CPU-native neural network inference optimization engine — making complex models runnable on hardware without a GPU. Takes an already-trained model (CNN or Transformer) and transforms it through quantization, structured pruning, graph-level optimization, and hand-written AVX2 CPU kernels into a form that runs with acceptable latency and memory footprint on constrained, no-GPU machines. Enforces a hard dev/target machine separation — the target build never installs PyTorch or any training framework, only the compiled C++ runtime and its artifact.

Currently has a verified FP32 vertical slice for ResNet-18: the C++ runtime's output matches PyTorch's reference to a max absolute difference of 3.93e-06, and a hand-tuned AVX2 GEMM micro-kernel cut mean inference latency from 397.4ms to 140.9ms on the development machine. Quantization, pruning, and the transformer path are next on the milestone queue.

03 RESEARCH · targeting TMLR
RESEARCH KV Cache Compression Study

Empirical analysis comparing KV cache compression strategies — budget truncation, H2O token eviction, StreamingLLM, INT4/INT8 quantization, and sliding window attention — across OPT-1.3B, IBM Granite-1B, and Qwen2.5-1.5B. Documents architecture-specific failure modes including an H2O positional incoherence bug with RoPE models. Validated on smaller-parameter variants; now scaling to larger models.
